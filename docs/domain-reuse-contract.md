# 独立站与 HR 复用契约

客服核心按 `tenant_id` 隔离知识、语料、会话记忆、反馈候选和发布版本。独立站、店铺和 HR 组织可以共用同一套 `CustomerServiceCore`、导入接口和反馈闭环；每个租户必须单独配置业务资料、SOP、权限和发布人。

仓库内置 `ecommerce` 与 `hr` 两个领域 profile（由 `BUSINESS_DOMAIN` 选择），启动时会校验领域配置；profile 只提供业务标签和说明，不参与关键词路由。

## 业务映射

意图识别仍由共享 DeepSeek Flash 模型完成。核心的四个控制桶是稳定的执行边界，不是电商关键词表：

| 核心桶 | 电商示例 | HR 示例 |
|---|---|---|
| `product_inquiry` | 商品、价格、发货政策 | 薪酬福利、制度、岗位信息咨询 |
| `after_sales` | 订单、退换货、物流处理 | 请假、报销、入职材料等事项办理 |
| `complaint` | 服务投诉、履约争议 | 薪资争议、歧视或合规申诉 |
| `chitchat` | 问候、无明确诉求 | 问候、无明确诉求 |

业务差异通过租户知识和 SOP 注入，不通过新增关键词路由分支实现。若 HR 需要更细的标签，细分标签应由领域配置或后续模型结构化字段承载，并保留上述控制桶作为权限与人工接管边界。

## 接入顺序

1. 创建独立租户并配置认证密钥、组织范围和 `subject_hash_key`。
   独立站调用 `/v1/chat` 时必须传入经过宿主确认的 `context.store_id`（以及必要的 `platform`），否则店铺专属商品知识会被租户/店铺范围过滤。
2. 在 `/admin` 导入制度、产品或岗位资料；PDF 导入必须保留来源页码和原件。
3. 配置该租户的 SOP、敏感字段和可执行工具；默认只允许回答和人工接管。
4. 用真实对话、图片和歧义问句做评测，再将反馈候选按 `evaluate → approve → rollback` 发布。
5. 生产启用真实 embedding 后，对该租户知识全量重建索引，并保留版本、来源和审计记录。

当前仓库已真实验证电商 Demo 的上述导入、反馈和回滚闭环；真实独立站渠道、HR 数据授权、HR 专属 SOP 和领域评测集仍需接入方提供后才能验收。
